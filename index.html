Honest limits
What doesn't work yet

What I'd fix with more time.

Translation latency: Translation runs after each completed sentence, so there is a ~0.5–1 second delay between speech ending and the translated text appearing. It is near real-time, not instant.

Single-speaker limitation: The current version works best with one speaker at a time. Without speaker diarisation, overlapping voices or panel discussions can produce mixed transcripts.

Internet dependency: The system requires an internet connection and has no offline fallback, so if either API drops, the session stops.

POC-level resilience: Error handling is still at proof-of-concept level, with no auto-reconnect, session logging, or crash recovery.

Model trade-off: Some higher-performing models are available at a higher cost, while several of the most advanced options still do not support Vietnamese.

UI scope: As this is a POC, I used PyQt6 to build a simple desktop interface quickly. With more time, this could be developed into a more advanced web-based UI or a more polished production application.

Voice generation: Uses ElevenLabs for high-quality voice output.

How I worked
Agentic coding journey

AI is a powerful tool. Understanding is still on me.

I did bring AI into my implementation process, but mainly as a development assistant rather than as something that built the project for me. For this AI interpreter POC, I used AI to compare speech-to-text and translation model options, brainstorm the system flow, generate boilerplate, help debug issues, and quickly look up syntax or library patterns while verifying everything against the official documentation. It was especially useful when I was working across unfamiliar areas at once, like AssemblyAI streaming, Google Cloud Translate, threading, queues, and PyQt6 UI development.

In terms of technique, this was less about multi-agent orchestration or RAG, and more about practical AI-assisted engineering. I used iterative prompting to refine implementation steps, break problems into smaller parts, and test alternatives quickly. For example, I used AI to reason through how to keep transcription responsive while running translation in the background, then I validated the threading model, queue behaviour, and API usage myself before committing to the design. So my approach was to use AI to accelerate exploration and implementation, but still make sure I understood the architecture, trade-offs, and technical decisions behind the final system.
